# ADR-0001: 向量库选用 ChromaDB

- **状态**：已采纳
- **日期**：2026-06-14

## 背景 / 问题
RAG 需要一个向量库存放文档 embedding 并做相似度检索。选型要平衡：本地开发的易用性、零/低运维、与 LangChain 的集成、当前数据规模（文档级，向量数 < 1M）。

## 候选方案
| 方案 | 优点 | 缺点 |
|------|------|------|
| **ChromaDB（选中）** | 可嵌入进程、零基础设施即可本地跑；LangChain 原生集成（`langchain-chroma`）；支持持久化 | 不面向超大规模/高可用；分布式能力弱 |
| pgvector（Postgres 扩展） | 复用现有关系库、事务、SQL 过滤强 | 需要跑 Postgres；调优门槛更高 |
| Pinecone / 托管服务 | 全托管、可扩展、免运维 | 付费、外部依赖、数据出域；本地开发不方便 |
| FAISS | 极快、成熟 | 只是索引库，缺元数据/持久化/服务化，得自己包一层 |

## 决策
选 **ChromaDB**：当前是文档级规模的问答服务，ChromaDB 能**零运维本地起步**、和 LangChain 无缝对接，最快跑通端到端。

## 权衡 / 代价
- 放弃了大规模/高可用能力——可接受，因为当前非目标（见 README Non-goals）。
- **迁移路径**：当向量数逼近百万级或需要 HA/多租户时，切到 **pgvector**（若已有 Postgres）或**托管服务**。检索层已通过 LangChain 的 `VectorStore` 抽象，替换成本可控。

## 结果 / 回顾
